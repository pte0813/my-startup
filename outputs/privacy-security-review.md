## 2. 이상 없음으로 확인한 것
- 모든 표 RLS 활성. 방문자는 `signups`·`inquiries`에 넣기만 가능하고 읽을 수 없음. `payments`·`ai_*`·`reunion_picks`는 서버(service_role)만 접근.
- 이름·이메일은 AI에 보내지 않음. AI에는 정해진 선택지 값만 전달(자유 입력이 프롬프트로 들어가지 않음). 후기 본문은 "자료"로만 취급해 본문 속 지시문을 따르지 않게 함.
- 카드번호는 수집·저장하지 않음(나이스페이먼츠가 처리). 결제 금액은 서버가 DB 가격으로 정함.
- DB 위치는 대한민국(서울).
- 비밀 키(ANTHROPIC·SERVICE_ROLE)는 서버 환경변수에만 있고 브라우저 코드에 없음.

## 3. 알고 계셔야 할 한계(허용한 위험)
- `trip_counts` 뷰는 신청 인원수만 공개하려고 일부러 보안 정의자(SECURITY DEFINER)로 만들어 어드바이저가 "오류"로 표시합니다. 개인 정보는 없습니다.
- `reviews` 조회에서 작성자 `user_id`(무작위 식별자)가 함께 보이고, 후기 사진 주소에 이 식별자가 들어 있습니다. 이름·이메일과는 연결되지 않습니다.
- 재만남 후보 목록에는 같은 여행 참가자끼리 프로필 이름이 보입니다(선택하신 방식).
- CSP는 `account.html`의 인라인 스크립트 때문에 `'unsafe-inline'`을 허용합니다. 나이스페이먼츠 결제창은 **실제 키로 결제해 보기 전까지 CSP와의 호환을 확인하지 못했습니다.** 결제가 막히면 `vercel.json`의 `Content-Security-Policy`를 먼저 의심하세요.
- 신고·차단 기능과 이용약관은 아직 없습니다.

## 4. 오픈 전에 사람이 해야 할 일
1. **법률 검토**: 처리방침·동의 문구(초안) 확정, 개인정보 보호책임자 이름·연락처 입력(`src/pages/privacy.html`의 `[입력 필요]` 두 곳), 이용약관 작성.
2. **Vercel 환경변수** `CRON_SECRET` 등록(임의의 긴 문자열) → 주간 파기 크론 작동.
3. **Supabase 설정**: Auth → 비밀번호 보안의 "유출된 비밀번호 차단" 켜기(요금제에 따라 제공), 이메일 확인(Confirm email) 다시 켜기, 비밀번호 최소 길이 상향 검토.
4. **Supabase SQL 편집기**에서 `drop function public.zz_probe();` 실행.
5. Resend 키·Anthropic 키는 채팅에 붙여넣은 적이 있다면 새로 발급.
6. 사전 신청(`signups`) 데이터 파기 시점 결정(처리방침에는 "출시 안내 후 또는 요청 시"로 적음).
7. 나이스페이먼츠 테스트 결제로 CSP 호환 확인.
